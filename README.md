# ETWWPFApp

## 📖 Project Overview
`ETWWPFApp` is a high-performance WPF application demonstrating how to consume **Event Tracing for Windows (ETW)** to capture and analyze system-level telemetry. Built with `.NET 10`, this application showcases practical implementations of both real-time monitoring (**Live Sessions**) and post-incident forensics via **ETL file parsing**, specializing in tracing process lifecycle, thread behavior, and dynamic image/DLL loading events.

- **Target Framework**: `.NET 10.0`
- **Core Technology**: `Microsoft.Diagnostics.Tracing.TraceEvent`
- **Key Focus**: ETW Real-time Consumer Architecture, Multi-threaded Data Buffering, and High-Throughput WPF UI Optimization.

---

## ✨ Key Features
- **Real-Time Live Session**: Captures live Windows kernel/system telemetry dynamically (Requires Administrator Privileges).
- **Post-Mortem ETL Forensic**: Parses offline `.etl` log files generated by standard diagnostic tools like PerfView or logman.
- **Granular Telemetry Tracing**:
  - **Process Lifecycle**: Tracks `ProcessStart`/`ProcessStop` with associated PIDs and Process Names.
  - **Thread Synchronization**: Monitors `ThreadStart`/`ThreadStop` tied to their respective parent PIDs/TIDs.
  - **Dynamic Image Loading**: Captures `ImageLoad` events, identifying loaded modules, DLL names, and their Base Addresses in memory.

## 🚀 Usage & Workflow
1. **Live Monitoring Mode**  
   - Launch the application with **Administrator privileges** (mandatory for managing kernel ETW sessions).
   - Select the **Live** mode option and click **"Start Live"**.
   - The engine will dynamically stream live kernel events into the diagnostic dashboard.

2. **ETL Log Parsing Mode**  
   - Select the **From ETL** mode and click **"Open ETL"**.
   - Browse and select any standard `.etl` trace file (e.g., generated via PerfView).
   - The application will parse the binary trace sequentially and reconstruct the system event logs.

## ⚖️ High-Throughput Performance Optimization
Handling kernel-level ETW telemetry exposes the application to massive data throughput (especially with high-frequency events like `ThreadStart/Stop` and `ImageLoad`), which can easily bottleneck the UI thread. This project implements the following engineering strategies to achieve lag-free rendering:

- **Asynchronous Decoupling Architecture**: Utilizes a `ConcurrentQueue<T>` data pipeline to decouple the intensive background ETW consumer thread from the foreground UI rendering loop.
- **UI Dispatcher Throttling**: Implements optimized `Dispatcher` scheduling to batch UI updates, ensuring the application remains highly responsive during extreme kernel traffic.
- **Telemetry Filtering (Target PID)**: Minimizes data bloat by allowing users to scope monitoring down to a specific Target PID, reducing memory and processing overhead.
- **Volatile Ring Buffering**: Limits the maximum capacity of the data visualizer (ListBox) to recent *N* events, preventing unbounded memory growth and memory-leak-like UI stutter.
- **Latency Tolerant Design**: Accommodates the inherent 0.5–2 second buffering latency of the native ETW infrastructure while ensuring event processing completeness.
